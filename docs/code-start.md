# Первое вычислительное ядро

Реализовано на Python с NumPy. Формулы описаны в [спецификации](diam-20k-6dof-model.md).

## Запуск

Из корня репозитория, Python 3.11 или новее:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python -m unittest discover -s tests -v
```

На Windows активация окружения выполняется через `.venv\Scripts\Activate.ps1`.

## Что работает

- Вектор состояния из 13 компонентов: N,E,D; u,v,w; q0,q1,q2,q3; p,q_body,r.
- Единичный кватернион Гамильтона, скаляр первым, преобразование из корпуса в NED.
- Уравнения Ньютона—Эйлера для постоянной массы и полного тензора инерции.
- Один шаг интегрирования RK4 с пересчётом сил на промежуточных состояниях.
- Расчёт момента силы по плечу от центра масс и свободного реактивного момента.
- Воздушная скорость с учётом ветра, скоростной напор, углы атаки и скольжения.
- Проверка массы, инерции, формы и конечности входных массивов.

Все величины в СИ. Связанные оси: вперёд, вправо, вниз. Начало в ЦМ.
В `rhs` и `loads` передаются фактические силы без тяжести и моменты относительно ЦМ.
Тяжесть добавляется внутри уравнений один раз. Сила не равна команде газа.

`step_rk4(state, time_s, dt_s, body, loads)` принимает функцию
`loads(time_s, state) -> (force_body_n, moment_body_nm)`.
Обработчик получает отдельную копию состояния с нормализованным кватернионом.
Шаг интегрирования выбирается вызывающим кодом; автоматического контроля ошибки пока нет.

## Условный пример проверки механики

Следующие масса и инерция заданы исключительно для учебного тела. Они НЕ являются оценками параметров ДИАМ-20К.

```python
import numpy as np
from diam20k import RigidBody, rhs

test_body = RigidBody(mass_kg=2.0, inertia_kg_m2=np.diag([2., 3., 4.]))
state = np.zeros(13)
state[6] = 1.0
derivative = rhs(state, test_body, [0, 0, -2*9.80665], [0, 0, 0])
print(derivative)  # Равновесие: все производные равны нулю.
```

## Характеристики реального аппарата

`configs/diam20k.json` содержит опубликованные характеристики с источником и датой проверки. Пользователь выбрал конфигурацию без полезной нагрузки: `payload_mass_kg=0`.

Максимальная взлётная масса 30 кг не определяет массу пустого аппарата. Вычитать из неё 3–5 кг и считать результат паспортной массой без нагрузки нельзя: неизвестны заправка и комплектация. Инерция также не определяется по габаритам и максимальной массе без модели распределения масс.

Фактическая масса и тензор инерции оставлены `null`. Загрузчик `load_body` выдаёт понятную ошибку, пока эти данные не заполнены. Для заполненных параметров следует обновить `status` и добавить источник/метод определения.

Для запуска механики с известными внешними силами необходимы:

1. Полная масса выбранной конфигурации, включая топливо, при нулевой полезной нагрузке.
2. Тензор инерции относительно центра масс в связанных осях.
3. Начальное состояние и закон сил/моментов во времени.

Для получения сил из положения рулей и команд двигателей дополнительно нужны аэродинамические коэффициенты, геометрия движителей и карты тяги. Эти зависимости пока не реализованы: произвольные коэффициенты не подставляются.

## Границы версии

Механическое ядро использует постоянные массу и инерцию. Контакт с землёй, бортовой автопилот и подтверждённая аэродинамика ДИАМ-20К отсутствуют. Вращение Земли и кривизна поверхности не учитываются. Нулевые тяги при исходном покое означают свободное падение, а не стоянку на земле.

Проверки охватывают аналитическое свободное падение, баланс сил при висении, направления осей и моментов, постоянную угловую скорость, сохранение энергии/импульса при свободном вращении с полным тензором инерции и обработку отсутствующих данных.

## Python или C++

На этом этапе Python удобен для проверки формул и изменения структуры модели. NumPy выполняет матричные операции в скомпилированном коде, но накладные расходы Python остаются. Скорость выполнения конкретного симулятора пока не измерена; гарантировать реальное время нельзя.

Переход к C++ имеет смысл по результатам профилирования, если потребуется жёсткое реальное время, встраиваемое выполнение или много одновременных траекторий. Текущие соглашения о состоянии, нагрузках и тесты физических инвариантов можно сохранить при переносе.

## Воспроизведение полёта над картой

После установки пакета создайте HTML-файл и откройте его в браузере:

```sh
python -m diam20k.map_flight
```

Команда создаёт `map-flight.html` в текущем каталоге и выводит полный путь.
Для другого файла или географической точки отсчёта укажите, например,
`python -m diam20k.map_flight --origin 55.75 37.62 150 --output replay.html`.
Выберите новое имя при повторной генерации. Файл открывается локально,
без сервера, подключения к интернету и ключей доступа.

Нажмите «Пуск» для воспроизведения. Ползунок перемещает по записанным состояниям,
кнопка «Сменить проекцию» меняет проекцию. Карта показывает препятствия с высотами,
целевую точку и траекторию с выделением уже пройденного участка.
Положение, ориентация (крен, тангаж, курс корпуса) и скорости берутся из
состояний RK4 с интервалом 0,05 с. Перед записью каждого нового состояния
проверяется отрезок, пройденный центром аппарата. При пересечении препятствия
или границы запись заканчивается на последнем допустимом состоянии.

Режим `flat` использует плоскую землю на `D = 0`. Положение NED в метрах
привязано к локальной линейной аппроксимации WGS 84. Север меняет широту,
восток меняет долготу, высота над уровнем карты равна `−D`. Третий параметр
начала отсчёта задаёт высоту этого уровня над эллипсоидом WGS 84, поэтому
эллипсоидальная высота в телеметрии равна `H₀ − D`. Привязка рассчитана
на участок размером в несколько километров. Высота над поверхностью равна `−D − hземли(N,E)`.

Полигон занимает 4400 × 1200 м. Из 16 препятствий восемь пересекают прямую
между стартом и целью. Перед расчётом программа группирует объекты по
перекрывающимся северным координатам и выбирает свободный поперечный проход
в каждой группе. Между группами проходы соединены гладкими кривыми. Поиск
ограничен движением на север и одним проходом на группу. Если такой вариант
не найден, генератор сообщает координаты проблемного участка.

В расчёте используются условные масса и инерция, заданная результирующая сила
и упрощённый момент разворота корпуса. Нагрузки интегрируются методом RK4.
Боковой ветер действует с 20-й до 60-й секунды. Проверка каждого пройденного
отрезка учитывает запас 3 м по каждой координате. Сравнить со штилем можно
командой `python -m diam20k.map_flight --calm --output calm.html`.

## Связь сценария, карты и измерений

Команда карты принимает `--scenario route|hover|climb|wind|free-fall`. Сценарий
задаёт тело, начальное состояние и внешние нагрузки. Итератор `flight_states`
интегрирует их тем же методом и с тем же состоянием, что и отдельный запуск
`scenarios.run`. Карта проверяет каждый следующий отрезок и обрывает запись
перед первым недопустимым шагом. Для падения на полигоне выбраны высота 120 м
и время 4 с. Остальные проверочные сценарии сохраняют свои исходные условия.
При отсутствии `--body-config` используется проверочное тело массой 2 кг.
Опция принимает JSON структуры `configs/diam20k.json` с заполненными массой
и тензором инерции. Даже с заполненным файлом в режиме route сила задаётся
по геометрии курса. Режим не моделирует крыло, рули и силовую установку.

Базовый режим вычисляет идеальные показания приборов в центре масс. В режиме приборных частот кадр содержит последние выданные показания, а при проверке ИНС гироскоп и акселерометр получают шум и квантование. Гироскоп
измеряет угловую скорость в связанных осях, акселерометр — сумму негравитационных
сил, делённую на массу. Барометр использует изотермическую атмосферу с 101325 Па
и 288,15 К на уровне карты. Скоростной напор рассчитан для идеального приёмника,
ориентированного по потоку. GNSS выдаёт локальную геодезическую привязку и
скорость в NED. Магнитометр переводит заданное поле NED в оси корпуса;
без `--field-ned-ut N E D` поле неизвестно. Шум, смещение, задержка, место
установки и калибровки бортовых приборов пока неизвестны. Показания выводятся
для анализа, управление учебного маршрута использует состояние модели.

```sh
python -m diam20k.map_flight --scenario climb --instrument-rates --output climb-map.html
```

В режиме `--instrument-rates` интегратор делает шаг 5 мс. В браузере можно
скачать JSON с парами [время в секундах, показание]. Частоты взяты из README.
Без этой опции показания доступны только в кадрах, с шагом сценария.

### Учёт топлива

Маршрут по умолчанию показывает диапазон расхода GF40. В демонстрации `demo.py` расход меняется с нагрузкой. Для учёта по журналу можно передать один из двух CSV-файлов в UTF-8, время в секундах относительно
начала полёта. Журнал должен покрывать всю сохранённую часть расчёта.

- `--fuel-log fuel.csv`: заголовок `time_s,flow_kg_s`. Масса израсходованного
  топлива — интеграл измеренного массового расхода с учётом всех узлов журнала.
  Для объёмного расходомера допустим заголовок `time_s,flow_l_h`.
  Результат сохраняется в литрах и отображается в миллилитрах, плотность смеси не требуется.
- `--engine-log engine.csv`: заголовок `time_s,rpm,torque_nm,bsfc_g_kwh`.
  Для двигателя под нагрузкой мощность на валу в кВт равна
  `2π × rpm × torque_nm / 60000`. Расход в кг/с равен произведению мощности
  на удельный расход в г/(кВт·ч), делённому на 3 600 000. Удельный расход
  нужен для каждого режима. На холостом ходу используйте прямой расходомер.

Между отсчётами расход интерполируется линейно. Это учёт по внешним
данным. Параметр `--initial-fuel-l` задаёт начальный объём для расчёта остатка. В уравнениях движения масса и инерция постоянны. Режимы электрического подъёма и работа генератора
сами по себе не задают расход бензина. Объём бака и его заполнение неизвестны.
Для базового GF40 руководство приводит объём 300 мл и время 7–8 мин при полном
газе. Эти данные относятся к примеру для отдельного двигателя. [Руководство O.S.](https://www.os-engines.co.jp/english/line_up/engine/air/gas/manual/GF40_EG.pdf)

### Габариты и сравнение с записью испытания

Опция `--hull-m L B H` задаёт полную длину, ширину и высоту прямоугольной
оболочки с центром в ЦМ, по связанным осям, в метрах. Проверка учитывает
положение корпуса на каждом шаге, перемещение центра, поворот между соседними
ориентациями и прежний запас 3 м. Оболочка ограничивается проекциями на оси
карты; возможна консервативная остановка вблизи угла. Между отсчётами приняты
прямой отрезок и кратчайший поворот. При неизвестных габаритах остаётся проверка
центра, её тип подписан в записи. Оболочка уточняет проверку готового прохода.

Опция `--reference-log reference.csv` добавляет в итоги среднеквадратическую
ошибку высоты и вектора скорости. Заголовок CSV:
`time_s,height_above_map_m,vn_m_s,ve_m_s,vd_m_s`. Начало времени, уровень
карты и оси должны совпадать с экспериментом. Расчётные значения линейно
интерполируются в моменты измерения. Каждый отсчёт журнала получает одинаковый
вес. Экстраполяция за интервал симуляции запрещена.

### Выбор состава измерений для полигона

| Канал | Зачем он нужен проекту | Как проверить |
|---|---|---|
| BMI088, трёхосевые гироскоп и акселерометр | Независимое счисление движения и оценка накопленного дрейфа | `--inertial-check` добавляет к карте оценку по записи IMU при 200 Гц и итоговую ошибку. Начальные положение, скорость и ориентация известны, seed=42. Управление не использует эту оценку. |
| BMP390, давление | Проверка высоты относительно опорного давления | В отчёте сценариев видна ошибка высоты при постоянном смещении давления. |
| GNSS | Абсолютные координаты и скорость для сравнения | Проверяются знаки NED, привязка высоты и частота 5 Гц. В текущей модели GNSS идеален. |
| Магнитометр | Измерение направления поля в осях корпуса | Нужны заданное местное поле и ориентация; без поля показание отсутствует. |
| Приёмник воздушного давления | Отличает движение относительно воздуха от путевой скорости | В неподвижном относительно земли аппарате при ветре скоростной напор положителен. |
| LIDAR-Lite v3, дополнительный нижний дальномер | Измеряет расстояние до поверхности под аппаратом, в том числе до крыши | Вертикальный луч показывает высоту над поверхностью, наклонённый — наклонную дальность. |

Для дальномера используется одиночный луч из ЦМ вдоль +Z корпуса. Берётся
первое пересечение с геометрией карты, дальность округляется до сантиметра.
В серии 50 Гц отсутствие отражения записывается как null. Предел 40 м
производитель указывает для цели с отражательной способностью 70%. Материал
поверхности, засветка, ширина луча и аппаратные отказы в этот опыт не входят.
Это выбор для учебного комплекта; поставка этих приборов на ДИАМ-20К
не подтверждена. [Garmin, руководство и характеристики](https://static.garmin.com/pumac/LIDAR_Lite_v3_Operation_Manual_and_Technical_Specifications.pdf).

Кандидаты для остальных уже существующих идеальных каналов:

- u-blox MAX-M10S даёт внешнюю спутниковую точку отсчёта для проверки
  накопленной ошибки ИНС. Приёмник поддерживает одновременный приём четырёх
  систем. Для оценки на борту потребуются условия приёма и задержки конкретной
  конфигурации. [Паспорт u-blox](https://content.u-blox.com/sites/default/files/MAX-M10S_DataSheet_UBX-20035208.pdf).
- ST LIS2MDL измеряет три компоненты поля и позволяет сопоставить направление
  магнитного поля с разворотом корпуса. На гибридной машине особенно существенна
  проверка смещения при включении электрических двигателей. До измерений
  локального поля и магнитных помех точность курса неизвестна.
  [Паспорт ST](https://www.st.com/resource/en/datasheet/lis2mdl.pdf).
- Sensirion SDP33 измеряет перепад давления в пределах ±1500 Па.
  При воздушной скорости 40 м/с и плотности 1,225 кг/м³ расчётный напор
  составляет 980 Па. Диапазон охватывает эту контрольную точку. Для проверки
  точности нужны характеристики приёмника полного и статического давления
  и сравнение с эталонным перепадом. [Паспорт Sensirion](https://sensirion.com/media/documents/6B7302AA/6375F33C/DP_DS_SDP33_D1.pdf).

Для баланса энергии нужны раздельные измерения. Для ДВС — расход топлива
(масса или объём в единицу времени), для электрической части — напряжение
и ток батареи и генератора. Выбор конкретных преобразователей требует
диапазонов токов, напряжений и расходов именно этой установки: мощность
ДВС сама по себе их не задаёт.

### Просмотр топлива и подложки

Карточка «Топливо за полёт» показывает итог сразу, а при перемотке — накопленный
расход к выбранному моменту. Журнал расходомера даёт объём или массу; журнал
положительных режимов с удельным расходом даёт оценку массы по мощности на валу.
Для маршрута без журнала отдельно показана сценарная оценка при работающем весь
интервал GF40. Пример O.S. с 300 мл на 10–15 минут соответствует 1,2–1,8 л/ч.
Вместо этого диапазона можно задать свой расход опцией `--fuel-rate-l-h`,
включая ноль для выключенного ДВС. На других сценариях без журнала или явно
заданного расхода режим двигателя неизвестен. Итог по времени не моделирует
изменение нагрузки, бак и запас хода. [Руководство O.S.](https://www.os-engines.co.jp/english/line_up/engine/air/gas/manual/GF40_EG.pdf)

Для демонстрации выбрана точка 37,45° с. ш., 110,61° з. д. (Юта, США).
1300 м — условная высота плоскости полигона над эллипсоидом. В HTML встроена
отмывка реального рельефа, вычисленная из тайла Terrarium 12/789/1587.
В режиме `flat` отмывка служит подложкой. Режим `utah` использует высоты того же тайла для отрисовки склонов, дальномера и проверки зазора. Вне участка показывается обычная сетка.
Данные рельефа США предоставлены USGS; источник — Mapzen Terrain Tiles, получено

Опция `--battery-log battery.csv` добавляет в итоги отданную и принятую энергию
в Вт·ч. Столбцы: `time_s,voltage_v,current_a`; положительный ток направлен
из батареи. Между отсчётами линейно интерполируется измеренная клеммная мощность
U × I. При переходе от разряда к заряду интервал разделяется по нулю мощности.
Журнал должен покрывать запись полёта. Эти числа не определяют ёмкость батареи,
остаток заряда или распределение энергии между двигателями.


## Демонстрационные расчёты

`python demo.py` создаёт три отчёта в новой папке. Первый полёт можно повторить отдельно.

```sh
python -m diam20k.map_flight --surface lab --hull-m 2 4 1 --gnss-outage 60 80 --field-ned-ut 20 0 40 --drive-profile configs/lab-drive.json --initial-fuel-l 1 --output training.html
```

**Поверхность.** Режим `lab` задаёт учебные гряды. В режиме `utah` из высот каждого узла вычтена отметка поверхности на старте. Высота WGS 84 в телеметрии привязана к условному нулю 1300 м. Для проверки зазора нужны только относительные высоты. Бинарный исходник Terrarium декодирован, пересчитан с учётом центров пикселей и сохранён с шагом 50 м и округлением до сантиметра. Округление описывает формат хранения. Сетку можно воспроизвести командой `python scripts/sample_terrain.py tile.png grid.json` после установки проекта и Pillow. [Исходный тайл](https://s3.amazonaws.com/elevation-tiles-prod/terrarium/12/789/1587.png).

Для дальномера луч пересекает треугольники сетки и учебные объёмы. При проверке движения отрезок делится на границах треугольников. Для габаритов используется нижняя оценка зазора с учётом наибольших уклонов под огибающей. Момент первого отклонённого шага и последний принятый кадр выводятся отдельно. Коричневые объёмы заданы в системе координат полигона. В таблице проходов зазор отсчитывается от центра до указанной грани на участке между продольными гранями препятствия.

**Топливо и электрическая энергия.** В `configs/lab-drive.json` задана учебная нагрузочная характеристика. Механическая мощность вычисляется по записи как `P = F·v + M·ω`, где сила исключает тяжесть. Эквивалентная потребная мощность равна `P₀ + max(P, 0)/η`. Базовая мощность установившегося хода P₀ равна 100 Вт, КПД η равен 0,8. Отрицательная работа рассеивается. Расход интерполируется по таблице мощности на валу и интегрируется по времени с учётом переходов через узлы. Выше предела таблицы отчёт показывает недостающую энергию и отмечает превышение мощности в результате. Итог траектории и проверка ресурсов рассчитываются последовательно. Если заданного бензина мало, отчёт показывает нехватку. Электроника потребляет отдельно заданные 18 Вт. Это условия опыта для проверочного тела. Для разбора клеммной энергии батареи предусмотрен отдельный журнал `--battery-log`.

**Проверка механики.** Итоги показывают интеграл работы сил и моментов, изменение суммы кинетической и потенциальной энергии и максимальную абсолютную разность этих величин за весь полёт. Проверка включает вращательную энергию и использует интервалы между сохранёнными кадрами.

**Пропадание GNSS.** Опция `--gnss-outage A B` убирает спутниковые измерения на интервале [A, B). Во время пропуска в журнале стоит `null`. Приборы обновляются на своих частотах. При проверке ИНС в JSON и на экране доступны те же зашумлённые отсчёты IMU, по которым велось счисление. Эталонное положение модели показывается отдельно в телеметрии. В отчёте доступны полная ошибка от старта и ошибка *приращения* после последней спутниковой отметки. Вторая отсчитывается заново при поступлении отметки. Обе величины вычисляются при разборе записи; регулятор маршрута использует состояние модели. Вектор магнитного поля и начальный запас 1 л выбраны для демонстрации.

Для восстановления траектории после полёта по каждой доступной отметке GNSS
вычисляется разность между позицией приёмника и инерциальной оценкой.
Внутри пропуска поправка к ИНС линейно интерполируется между отметками с двух
сторон. Полученную позицию сравнивают с эталоном только после восстановления.
За краями интервала спутниковых отметок результат отсутствует. В итогах
показана максимальная ошибка восстановления. Эта обработка требует будущей
отметки и доступна при разборе записи.
