# Первое вычислительное ядро

Реализовано на Python с NumPy. Формулы описаны в [спецификации](diam-20k-6dof-model.md).

## Запуск

Из корня репозитория, Python 3.11 или новее:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python -m unittest discover -s tests -v
```

На Windows активация окружения выполняется через `.venv\Scripts\Activate.ps1`.

## Что работает

- Вектор состояния из 13 компонентов: N,E,D; u,v,w; q0,q1,q2,q3; p,q_body,r.
- Единичный кватернион Гамильтона, скаляр первым, преобразование из корпуса в NED.
- Уравнения Ньютона—Эйлера для постоянной массы и полного тензора инерции.
- Один шаг интегрирования RK4 с пересчётом сил на промежуточных состояниях.
- Расчёт момента силы по плечу от центра масс и свободного реактивного момента.
- Воздушная скорость с учётом ветра, скоростной напор, углы атаки и скольжения.
- Проверка массы, инерции, формы и конечности входных массивов.

Все величины в СИ. Связанные оси: вперёд, вправо, вниз. Начало в ЦМ.
В `rhs` и `loads` передаются фактические силы без тяжести и моменты относительно ЦМ.
Тяжесть добавляется внутри уравнений один раз. Сила не равна команде газа.

`step_rk4(state, time_s, dt_s, body, loads)` принимает функцию
`loads(time_s, state) -> (force_body_n, moment_body_nm)`.
Обработчик получает отдельную копию состояния с нормализованным кватернионом.
Шаг интегрирования выбирается вызывающим кодом; автоматического контроля ошибки пока нет.

## Условный пример проверки механики

Следующие масса и инерция заданы исключительно для учебного тела. Они НЕ являются оценками параметров ДИАМ-20К.

```python
import numpy as np
from diam20k import RigidBody, rhs

test_body = RigidBody(mass_kg=2.0, inertia_kg_m2=np.diag([2., 3., 4.]))
state = np.zeros(13)
state[6] = 1.0
derivative = rhs(state, test_body, [0, 0, -2*9.80665], [0, 0, 0])
print(derivative)  # Равновесие: все производные равны нулю.
```

## Характеристики реального аппарата

`configs/diam20k.json` содержит опубликованные характеристики с источником и датой проверки. Пользователь выбрал конфигурацию без полезной нагрузки: `payload_mass_kg=0`.

Максимальная взлётная масса 30 кг не определяет массу пустого аппарата. Вычитать из неё 3–5 кг и считать результат паспортной массой без нагрузки нельзя: неизвестны заправка и комплектация. Инерция также не определяется по габаритам и максимальной массе без модели распределения масс.

Фактическая масса и тензор инерции оставлены `null`. Загрузчик `load_body` выдаёт понятную ошибку, пока эти данные не заполнены. Для заполненных параметров следует обновить `status` и добавить источник/метод определения.

Для запуска механики с известными внешними силами необходимы:

1. Полная масса выбранной конфигурации, включая топливо, при нулевой полезной нагрузке.
2. Тензор инерции относительно центра масс в связанных осях.
3. Начальное состояние и закон сил/моментов во времени.

Для получения сил из положения рулей и команд двигателей дополнительно нужны аэродинамические коэффициенты, геометрия движителей и карты тяги. Эти зависимости пока не реализованы: произвольные коэффициенты не подставляются.

## Границы версии

Нет контакта с землёй, автопилота, датчиков, расхода топлива, изменения инерции и подтверждённой модели аэродинамики ДИАМ-20К. Вращение Земли и кривизна поверхности не учитываются. Нулевые тяги при исходном покое означают свободное падение, а не стоянку на земле.

Проверки охватывают аналитическое свободное падение, баланс сил при висении, направления осей и моментов, постоянную угловую скорость, сохранение энергии/импульса при свободном вращении с полным тензором инерции и обработку отсутствующих данных.

## Python или C++

На этом этапе Python удобен для проверки формул и изменения структуры модели. NumPy выполняет матричные операции в скомпилированном коде, но накладные расходы Python остаются. Скорость выполнения конкретного симулятора пока не измерена; гарантировать реальное время нельзя.

Переход к C++ имеет смысл по результатам профилирования, если потребуется жёсткое реальное время, встраиваемое выполнение или много одновременных траекторий. Текущие соглашения о состоянии, нагрузках и тесты физических инвариантов можно сохранить при переносе.
